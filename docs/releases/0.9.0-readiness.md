# codr 0.9.0 release verification

## Source and build identity

The release preserves approved stable history, including Juraj Bednar's original
PR #16 commits. Its focused implementation was reviewed in candidate
`412df0f95dd7411792a9a84f886432aec8ae8f74` on stable `5027a14`.
The final follow-up changes release documentation only, not executable source,
dependency pins, updater logic, connector patch, wire format or state schema.

The [candidate build](https://github.com/tidley/codr/actions/runs/40787701828)
records its own source and artifacts. Those artifacts must not be relabelled as
the final documentation commit. The existing `v0.9.0` tag workflow checks and
builds the exact release source again; it has no supported artifact-promotion path.
Keep that tag run's provenance and checksums with the published release.

## Included and excluded scope

Included: paginated folder filtering, `/last`, optional `/recent` hour windows,
original UTC source dates, chat-scoped `/cancel`, clearer invitations, non-owning
OpenCode HTTP observation, fresh Claude history, EOF-only CLI retries, bounded
warning throttling and updater/mute-wake regression tests.

Excluded: Foreman orchestration, worker-sharing filters, combined runtime,
vendored MDK, new storage cohort and SQLCipher dependency migration. The connector
pin and bridge/connector separation are unchanged. A bridge update is not
permission to migrate MDK 0.13 account storage.

## Release and mirror verification

1. Require Linux/macOS checks, formatting, strict Clippy and all four platform
   packages from the exact tag workflow. Do not bypass required gates.
2. Record source, version, platforms, build inputs, test results and provenance.
   Download each GitHub archive and checksum file; verify SHA-256 and completeness.
3. Mirror approved source refs and tags to ngit with matching hashes. Upload the
   exact GitHub assets and checksum files to Blossom without rebuilding,
   repackaging or re-signing binaries. Mirror version, source, release date,
   stable channel and identical notes/contributor credits.
4. Download every mirrored file and compare it with the verified GitHub original.
   Check existing records before retrying; never replace conflicting releases or
   create duplicates. Tom approves `devbox-amber` signing requests in Amber.
5. Keep original GitHub CI run links. The installed ngit 3.0.3 CLI has no CI-result
   import command; CI-event mirroring is blocked unless supported tooling becomes
   available. Do not invent a CI event or rebuild merely to mirror evidence.

See [MIRRORING.md](../MIRRORING.md). GitHub publication, verified mirrors, installed
version and a successful phone update remain separate states.

## Phone update test

1. Wait for the signed stable mirror and all download verification. A CI artifact
   or GitHub-only release is not discoverable by `/update`.
2. Check the managed worker and shared OpenCode process ownership/guard. Record
   private preservation evidence for accounts, mappings, accepted deliveries,
   native sessions, history and sync settings. Do not expose credentials.
3. From the owner's phone, send `/update`. Confirm that it offers **0.9.0**.
   `/update cancel` dismisses an offer without installing; request it again when
   ready. Use the fresh ten-minute confirmation command only for the intended version.
4. Verify completion goes to the original chat, the worker reports 0.9.0, its
   executable matches the approved artifact, and existing state/shared server
   identities remain intact. Keep rollback evidence.

Do not pre-install the worker, inject a synthetic release, change trust roots or
bypass signature/checksum/cohort checks to make this test pass. The phone's
confirmation is the explicit installation action.
