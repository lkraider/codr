# **codr** 0.6.1 — Linux preview

This is an opt-in prerelease from `dev/linux`, for Linux x86-64 and ARM64 only.
The latest stable, cross-platform release remains `v0.6.0`.

## Changes

- Editable `working...` progress keeps the current to-do list while a final reply
  is still being saved. Completed replies are separate messages, not edits to
  the progress bubble.
- Completed progress preserves checklists from both the old and new working labels.
- Pending OpenCode V2 questions are read from live session forms, restoring
  supported phone-side decision cards. Existing visible-terminal checks remain.
- Send `unmute` or `/unmute` by itself in any linked White Noise chat to resume
  forwarding for all chats without prompting or answering an agent.

## Install or upgrade

```sh
herdr plugin install tidley/codr --ref v0.6.1
herdr plugin action invoke local.white-noise.setup
```

Use the version tag, not the moving development branch. Setup preserves the
configured owner, connector account, group mappings, and consumed-message history.
It selects the version-matched connector path without creating a replacement identity.

macOS users should stay on `v0.6.0`; this preview declares Linux-only support.

## Build provenance

The workflow runs the Rust tests, formatting, Clippy, and Python tests on Linux,
then builds static musl bridge binaries on native x86-64 and ARM64 runners.
It does not run macOS jobs or rebuild unchanged MDK source.

The dedicated connector executable and license are reused byte-for-byte from
`v0.6.0`. Reuse requires the published archive checksum and its repository,
source revision, upstream version, and patch checksum to match `connector.toml`
and `patches/mdk-codr.patch`. A mismatch fails the preview and requires a rebuild.
`CODR-CONNECTOR.json` records the original package version and source-archive
checksum, as well as the new package version. Each published archive has a SHA-256
sidecar. No macOS assets are included, and this release is not marked latest.

For another preview, dispatch **Build and release** on the development branch
with `linux_preview=true` and `source_ref` set to the exact reviewed commit.
The workflow creates the prerelease tag with its GitHub Actions token so the
normal all-platform tag workflow is not triggered.
